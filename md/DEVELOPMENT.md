# راهنمای توسعه

## پیش‌نیاز و راه‌اندازی

Node.js شاخه ۲۴ و npm شاخه ۱۱ مطابق engines در package.json لازم‌اند. مدیر بسته فقط npm است؛ package-lock.json حذف یا با lockfile دیگری جایگزین نشود.

```bash
npm ci
npm run dev
```

سرور توسعه معمولاً روی پورت 3000 اجرا می‌شود؛ اگر پورت در استفاده باشد، آدرس خروجی Next.js ملاک است. اطلاعات نسخه‌ها و تصمیم‌های وابستگی در [TECH_STACK.md](TECH_STACK.md) و وضعیت سرویس‌ها در [ARCHITECTURE.md](ARCHITECTURE.md) است.

## دستورهای روزمره

| دستور                   | کاربرد                                   |
| ----------------------- | ---------------------------------------- |
| npm run dev             | سرور توسعه Next.js                       |
| npm run build           | ساخت نسخه تولیدی                         |
| npm start               | اجرای خروجی تولیدی پس از build           |
| npm run lint            | Oxlint بدون پذیرش warning                |
| npm run typecheck       | تولید typeهای Next.js و بررسی TypeScript |
| npm test                | اجرای Vitest                             |
| npm run test:watch      | اجرای تست در حالت watch                  |
| npm run format          | قالب‌بندی پروژه با Prettier              |
| npm run format:check    | بررسی قالب‌بندی بدون تغییر فایل          |
| npm run check           | lint، typecheck، تست و بررسی قالب‌بندی   |
| npm run assets:generate | تولید لوگو، favicon و پیش‌نمایش پالت‌ها  |

## قواعد تغییرات

- پیش از تغییر API یا قرارداد Next.js، راهنمای مرتبط در node_modules/next/dist/docs خوانده شود؛ به دانش نسخه‌های قبلی اکتفا نشود.
- Tailwind روش اصلی استایل‌نویسی و daisyUI مرجع اجزا و تم است؛ جزئیات در [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).
- نسخه‌های مستقیم پایدار و سازگار انتخاب شوند. beta/RC، force و legacy-peer-deps برای دورزدن ناسازگاری استفاده نشوند.
- برای احراز هویت NextAuth انتخاب شده است؛ Better Auth جایگزین آن نشود.
- اجزای مشترک در components و منطق مشترک در lib یا hooks قرار می‌گیرند. ساختار و مسئولیت‌ها در ARCHITECTURE.md توضیح داده شده‌اند.
- مستندات موضوعی در md نگه‌داری شوند؛ فایل مستند جدا برای هر کامپوننت ساخته نشود.

## بررسی تغییرات

برای تغییرات کد، بررسی متناسب با دامنه اجرا شود. پیش از آماده‌کردن مجموعه تغییرات برای کامیت، دستورهای زیر بررسی کامل فعلی پروژه‌اند:

```bash
npm run check
npm run build
```

Vitest سبک با محیط Node، یک worker و بدون موازی‌سازی فایل‌ها تنظیم شده است. تست‌ها در tests قرار دارند و منطق تم، bootstrap، بازیابی تنظیمات و رنگ دلخواه و کنتراست برند و کامل‌بودن کاتالوگ‌های ترجمه را پوشش می‌دهند. آخرین اجرای ثبت‌شده در ۲۰۲۶/۱۱/۰۵، ۲۶ تست موفق داشت؛ تست تجاری ورود و خرید هنوز وجود ندارد.

برای تغییرات ظاهری و انیمیشن، بررسی واقعی مرورگر لازم است. حالت اولیه، حین حرکت، پایان حرکت، تعامل تکراری و مسیر اصلی دکمه بررسی شوند. در تعویض محصول چند بار بین هر سه محصول جابه‌جا شوید. برای تغییر responsive، عرض‌های مرتبط و اسکرول افقی بررسی شوند. بررسی مرورگر جای تست روی گوشی فیزیکی یا audit جامع دسترس‌پذیری را نمی‌گیرد.

Playwright، axe، jsdom و CI چندمرحله‌ای در وابستگی‌های پایه اضافه نشده‌اند. تست مرورگری خودکار باید هنگام پیاده‌سازی مسیرهای ضروری ورود یا خرید، بر اساس همان رفتار واقعی اضافه شود.

## دارایی‌ها و فایل‌های تولیدی

منبع هندسه لوگو scripts/generate-logo.mjs است؛ خروجی‌ها با assets:generate تولید می‌شوند. تصاویر مصرف‌شده سایت در public هستند و باید همراه تغییر مرتبط کامیت شوند. .next، node_modules، فایل‌های tsbuildinfo و خروجی محلی بررسی طراحی در .taste-skill نباید کامیت شوند. راهنمای دارایی و منشأ تصاویر در DESIGN_SYSTEM.md و ARCHITECTURE.md آمده است.

## امنیت وابستگی‌ها

گزارش تاریخ‌دار وابستگی‌های توسعه در [SECURITY.md](SECURITY.md) است. نتیجه قدیمی audit به‌عنوان نتیجه اجرای تازه گزارش نشود. ارتقای ابزار نصب کامپوننت یا تغییر registry باید با محدوده سازگاری و بررسی ورودی همراه باشد. ابزار shadcn فعلاً نصب است؛ رابط فعلی از daisyUI استفاده می‌کند.

## بررسی نسخه انگلیسی

در ۲۰۲۶/۱۱/۰۵، `npm run check` با ۲۴ تست و `npm run build` موفق شدند. نسخه تولیدی انگلیسی در مرورگر در عرض‌های ۳۹۰ و ۱۴۴۰ بررسی شد: رفت‌وبرگشت زبان، جهت سند، منوی موبایل، نتایج دسته‌بندی و جست‌وجو، تنظیم تم و معرفی محصول. تعویض تکراری هر سه محصول و فریم‌های میانی بررسی شدند؛ در عرض ۳۹۰ اسکرول افقی مشاهده نشد. آزمایش روی گوشی فیزیکی انجام نشده است.

در بازنگری تغییر زبان، تم تیره navy و پالت cobalt هنگام رفت‌وبرگشت فارسی/انگلیسی حفظ شدند؛ حالت روشن، Back مرورگر، تعویض تکراری هر سه محصول و فریم‌های میانی RTL/LTR در عرض ۳۹۰ نیز بررسی شدند. تغییر زبان بدون بارگذاری مجدد و با حفظ محصول انتخابی انجام می‌شود.

پس از جایگزینی fade با حرکت چیدمان، فریم میانی تغییر زبان در مرورگر با opacity بدنه برابر ۱ و transform فعال روی متن و محصول بررسی شد. رفت‌وبرگشت زبان، تعویض محصولات پس از آن و عرض موبایل ۳۹۰ بررسی شدند؛ lint، TypeScript، ۲۴ تست و بیلد موفق بودند.

## کنترل متن‌های رابط

پیش از افزودن متن قابل نمایش، کلید معنادار آن را در هر دو کاتالوگ ترجمه تعریف کنید و در کامپوننت از useTranslations بخوانید. برای جمله‌های دارای متغیر از پارامترهای ICU استفاده کنید؛ جمله را در JSX به قطعه‌های زبانی مستقل نچسبانید. برچسب اجزای عمومی باید از محل استفاده ترجمه و پاس داده شود. قرارداد کامل در [معماری](ARCHITECTURE.md#مرز-متن-قابل-ترجمه) است.

تست `tests/ui-copy.test.ts` با AST کامپوننت‌ها و فایل‌های TSX برنامه را برای متن مستقیم JSX، literal در ویژگی‌های متنی، فیلدهای اطلاعات نمایشی و مقدار پیش‌فرض برچسب بررسی می‌کند. این تست تحلیل کامل جریان داده نیست؛ متن‌های محاسبه‌شده و داده سرویس‌های آینده همچنان نیاز به بازبینی دارند. تست کاتالوگ‌ها نیز برابری کلیدهای تو‌در‌تو، متن غیرخالی، زبان انگلیسی و تطابق پارامترها را بررسی می‌کند.

بررسی ۲۰۲۶/۱۱/۰۵: نام لاتین سه محصول، برچسب پیش‌فرض لوگو و عنوان تب به کاتالوگ منتقل شدند؛ قالب برچسب رنگ‌ها و نشانه‌های متنی هم از کاتالوگ خوانده می‌شوند. `npm run check` با ۲۶ تست موفق و `npm run build` تأیید شدند.

### تست هم‌زمان زبان و تم

در ۲۰۲۶/۱۱/۰۵، گذار تم به ۱۰۰۰ میلی‌ثانیه تغییر کرد. در مرورگر تولیدی، ۶ تغییر ترکیبی زبان/تم در دسکتاپ، ۶ تغییر سریع پشت‌سرهم حالت و ۴ تغییر ترکیبی در عرض ۳۹۰ بررسی شدند. نمونه‌برداری میانی transitionDuration برابر 1s، رنگ‌های میانی متفاوت و localeMoving فعال را هم‌زمان نشان داد. در پایان data-theme-changing و data-locale-moving پاک شدند، حالت checkbox با تم نهایی تطابق داشت، اسکرول افقی موبایل وجود نداشت و خطای کنسول مشاهده نشد. این نتیجه محدود به مرورگر بررسی‌شده است؛ آزمون گوشی فیزیکی یا شبیه‌سازی reduced-motion انجام نشد.
